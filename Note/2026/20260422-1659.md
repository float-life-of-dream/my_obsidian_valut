后端架构
Used tool: Agent


## 后端模块概览

后端采用分层架构，从入口到基础设施逐层依赖：

```
run.py
  └─ app/__init__.py          ← 应用工厂
       ├─ app/config.py        ← 配置
       ├─ app/extensions/      ← 扩展实例
       ├─ app/api/             ← 路由/控制器层
       │    ├─ health.py       ← 健康检查
       │    └─ monitor.py      ← 监控 API
       ├─ app/schemas/         ← 数据校验 & 序列化
       │    └─ monitor.py      ← Marshmallow Schema
       └─ app/services/        ← 业务逻辑层
            ├─ monitor_service.py   ← 指标编排 & PromQL 定义
            └─ prometheus_client.py ← Prometheus HTTP 客户端
```

### 各模块职责

| 模块 | 职责 |
|---|---|
| **`run.py`** | 应用入口，通过 `create_app()` 创建 Flask 实例，启动开发服务器 |
| **`app/__init__.py`** | 应用工厂 —— 组装配置、CORS、flask-smorest 扩展、注册所有蓝图 |
| **`app/config.py`** | 集中配置 —— API 文档标题/版本、Prometheus 地址/超时、PostgreSQL 连接参数（均支持环境变量覆盖） |
| **`app/extensions/docs.py`** | 导出 flask-smorest `Api` 单例，用于自动生成 OpenAPI/Swagger 文档 |
| **`app/api/health.py`** | 健康检查 —— `GET /api/health` 返回 `{status, service, version}`，用于 K8s 存活探针 |
| **`app/api/monitor.py`** | 监控 API —— `GET /api/monitor/overview`（所有指标快照）和 `GET /api/monitor/timeseries?metric=&range=&step=`（时序数据） |
| **`app/schemas/monitor.py`** | Marshmallow Schema —— 定义请求参数校验（metric 枚举、range 可选值）和响应格式（overview/timeseries） |
| **`app/services/monitor_service.py`** | 核心业务逻辑 —— 定义 `METRIC_CONFIG`（4 个指标的 PromQL 查询和单位），`MonitorService` 编排 overview 和 timeseries 数据组装 |
| **`app/services/prometheus_client.py`** | 基础设施层 —— 对 Prometheus HTTP API 的薄封装，提供 `query()`（即时查询）和 `query_range()`（范围查询），统一异常为 `PrometheusClientError` |

### 数据流

```
请求 → Flask 路由 → API 蓝图 → Schema 校验参数
       → MonitorService → PrometheusClient → Prometheus HTTP API
       → 结果拼装 → Schema 序列化 → JSON 响应
```
