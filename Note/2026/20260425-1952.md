## How the workflow works

```
Push to main ──► Build ──► Deploy to GitHub Pages
                                 │
PR to main ───► Build only        │  (verify, no deploy)
                                 │
Manual dispatch ──► Build ───────┘
```

- **Build job** — checks out code, sets up Python 3.12, installs deps from `requirements.txt`, runs `mkdocs build --strict` (fails on warnings), uploads the `site/` artifact
- **Deploy job** — runs only on push/manual dispatch, uses the official `actions/deploy-pages@v4` to publish to GitHub Pages

## To activate it

1. Initialize git and push to GitHub:
    
    ```bash
    git init
    git add -A
    git commit -m "Initial blog setup with MkDocs Material"
    git remote add origin https://github.com/YOUR_USERNAME/YOUR_REPO.git
    git push -u origin main
    ```
    
2. Go to **Repo Settings → Pages → Source** and select **"GitHub Actions"**
3. The workflow runs automatically on the first push — your blog will be live at `https://YOUR_USERNAME.github.io/YOUR_REPO/`

Update the `site_url` in [mkdocs.yml](vscode-webview://00b7vb0ge44f06ehdr6qg8cfs5vn0ngfo7cgdhub94i1g9kovnq3/mkdocs.yml) to match your actual GitHub Pages URL once you know it.
