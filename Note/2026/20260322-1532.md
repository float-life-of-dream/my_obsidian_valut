[203移除链表元素](https://leetcode.cn/problems/remove-linked-list-elements/)
```python
# Definition for singly-linked list.

# class ListNode:

#     def __init__(self, val=0, next=None):

#         self.val = val

#         self.next = next

class Solution:

    def removeElements(self, head: Optional[ListNode], val: int) -> Optional[ListNode]:

        if not head:

            return head

        current = ListNode(next=head)

        point = current

        while point and point.next:

            if point.next.val == val:

                point.next = point.next.next

                continue

            point = point.next

        return current.next
```
在你的代码中，`current` 节点是一个**虚拟头节点（dummy head node）**。它的作用是为了简化对链表头部元素进行删除操作的逻辑。

让我们来解释为什么不能直接返回 `head` 节点：

1.  **处理头部元素被删除的情况：**
    *   假设原始链表是 `[7, 7, 1, 2]`，而你要删除的值 `val` 是 `7`。
    *   在你的代码中，`current = ListNode(next=head)` 会创建一个 `dummy -> 7 -> 7 -> 1 -> 2` 这样的结构。
    *   当 `point` 遍历到 `current` (即 `dummy`) 节点时，它会检查 `point.next` (即第一个 `7`)。
    *   由于 `point.next.val == 7`，代码会执行 `point.next = point.next.next`。这会将 `dummy` 的 `next` 指针从第一个 `7` 节点跳过，直接指向第二个 `7` 节点。
    *   这个过程会重复，直到 `dummy` 的 `next` 指针最终指向 `1` 节点。
    *   此时，`current.next` 正确地指向了新的链表头 `1`。
    *   然而，原始的 `head` 变量仍然指向最初的第一个 `7` 节点。如果你返回 `head`，你实际上返回了一个已经被删除的节点，并且它后面可能还连接着旧的、不完整的链表部分，这会导致结果错误。

2.  **`head` 变量未被更新：**
    *   在整个删除过程中，`head` 这个变量本身的值（它所指向的内存地址）从未被修改。它始终指向函数调用时传入的原始链表的第一个节点。
    *   所有的修改都是通过改变链表节点之间的 `next` 指针来完成的，例如 `point.next = point.next.next`。这些修改影响的是链表的结构，而不是 `head` 变量本身。

**总结：**

虚拟头节点 `current` 的作用是提供一个稳定的起点，无论原始链表的头部是否需要被删除，我们都可以通过 `current.next` 来获取到修改后链表的真正头部。

如果你直接返回 `head`，只有在原始链表的第一个节点不需要被删除时，结果才可能碰巧正确。一旦原始链表的第一个或前几个节点需要被删除，`head` 变量将不再指向链表的有效头部，从而导致错误。因此，返回 `current.next` 是确保始终返回正确修改后链表头部的安全做法。
